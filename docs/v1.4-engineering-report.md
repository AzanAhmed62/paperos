# PaperOS v1.4 engineering report

**Release:** PaperOS 1.4.0+5
**Application ID:** `dev.paperos.app`
**Schema:** version 2 (unchanged from v1.3)
**Report date:** 15 November 2026
**Status:** implementation and automated verification complete. No v1.4 device
run was performed. Production signing remains blocked.

This report records what was actually built, tested, analysed and audited on
this checkout. It does not convert a compile, a unit test or a widget test into
an Android device pass.

## Objective

v1.4 is a polish, reliability and measured-performance release:

- a custom Paper Home title stored in the existing settings document;
- one Search/Apps entry point on Home, with no duplicate launcher entry points;
- draft-first notes that never create a row until the user writes something;
- one deterministic app-drawer order across pinned, user and system apps;
- a coherent charcoal/off-white Ink reader without recolouring PDF bitmaps;
- a metadata-only EPUB probe at import and a background full parse in the reader;
- a one-pass copy plus SHA-256 import path with atomic rename;
- a picker that offers only formats this build can actually read;
- CI, versioning, documentation and honest verification labels.

The v1.3 architecture is preserved: five destinations, Riverpod, GoRouter,
SQLite schema v2, the existing PDF/TXT/EPUB/annotation/backup/SAF/launcher
surfaces, and the same application ID. No cloud service, analytics, ads,
backend, new navigation framework or broad storage permission was added.

## What changed

### Paper Home

- `HomeSettings.displayName` stores the heading in the versioned settings
  document. It is trimmed, an empty value falls back to `PaperOS`, and
  truncation is by Unicode code point at 32 characters so a surrogate pair is
  never split.
- The settings envelope is version 3. Version 1 and version 2 documents remain
  readable, and a missing title resolves to `PaperOS`.
- `SettingsController` serialises every settings write through one queue. Home
  title edits update in-memory state immediately and coalesce the disk write for
  350 ms; losing focus, leaving Settings, resetting, or taking a backup snapshot
  flushes the pending value.
- Home uses the custom heading and shows Search and Apps once, in the four-action
  row. The duplicate header icons, the pinned-section Apps link and the separate
  launcher app-drawer row were removed.
- The HOME-role setup notice appears only while PaperOS is not the default Home
  app. The layout adapts when Search or the clock is hidden.
- Home and Notes both push the static `/notes/new` route. The draft lifecycle
  lives in the editor, not in either caller.

### Draft-first notes

- A new editor generates a stable draft id but writes nothing on open.
- Untouched and whitespace-only drafts never insert a row.
- The first non-whitespace title or body save inserts exactly one row. Later
  saves update that row. Title-only and body-only notes are valid.
- Saves are serialised. Each queued save captures the latest text when it runs,
  so a debounce flush and a Back flush cannot apply an older revision last.
- Back flushes the latest keystrokes. A failed first save sets `Not saved`, keeps
  the text on screen, and blocks leaving with a toast.
- Delete marks the draft deleted before awaiting the write queue. If an in-flight
  insert completes after that mark, the editor deletes the row it just created
  instead of leaving an orphan.
- The repository exposes `insert` separately from `save`, and `NoteActions`
  forwards it, so the editor can distinguish a first insert from an update.

### App drawer

- `AppCatalogQuery.arrange` is the canonical order: pinned apps first in the
  user's pin order, then every remaining visible app in one case-insensitive
  A–Z sequence, including system apps when they are enabled.
- Ties break deterministically by label, then package name, then activity name.
  Duplicate packages collapse to one entry.
- Native catalogue enumeration now keeps the lexicographically smallest launcher
  activity per package, so the representative activity does not depend on
  Android's resolution order. It also performs the same label/package/activity
  stable sort before returning.
- The native `restricted` flag is now `false`. A short or empty list is not
  evidence of package-visibility restriction, and the drawer no longer claims
  one. Real platform failures still surface as channel errors.
- The drawer shows pinned apps in the Pinned strip and excludes them from the
  All apps rows while that strip is visible. Search still covers both.

### Ink reader

- The Ink palette is charcoal `#121211` on off-white `#E8E4DA`, not a pure black
  inversion.
- New `highlight` and `noteFill` tokens replace the reuse of `rule` for reader
  annotation backgrounds. Reader bars gain hairline rules.
- White and Warm retain their existing intent; the E-Ink display policy is
  untouched; PDF pages remain the original bitmap and are never recoloured.
- Unit tests enforce body/secondary/faint/inverse contrast floors, readable ink
  on highlight and note fills, distinct highlight/note tokens, and a non-pure
  Ink base.

### EPUB and import performance

- `EpubParser.probeFileAsync` reads and validates the archive, container,
  package, manifest and spine, then reads metadata and a safe cover only. It does
  not extract chapter text.
- `EpubParser.parseFileAsync` performs the full parse through `Isolate.run` when
  isolates are available and falls back to the calling isolate otherwise.
- The probe and full parse share one static serialised queue, bounding concurrent
  archive work. Results cross the isolate boundary as plain outcome DTOs carrying
  either a result or a user-facing failure string; no exception crosses it.
- The reader opens EPUB through the async parse. Import uses the metadata probe
  instead of a full-book parse.
- `LibraryService` copies the source once into `<destination>.part` while feeding
  the same chunks into SHA-256. It refuses an empty copy without touching an
  existing destination, renames only a complete copy, and deletes the duplicate
  copy after fingerprint detection. A successful import leaves no `.part` file.
- `DocumentFormat.importableExtensions` now aliases `readableExtensions`. The
  picker offers only PDF, TXT and EPUB. Recognised-but-unreadable formats remain
  clearly rejected in import and Files instead of being offered or falsely
  opened.
- External EPUB intents map to `document.epub`; the Android VIEW filter and
  `<queries>` now advertise `application/epub+zip` alongside PDF and text.

### Release engineering

- Version `1.4.0+5` in `pubspec.yaml` and `PaperConfig`.
- New GitHub Actions workflow at `.github/workflows/ci.yml` for format, analyse,
  full test and a debug APK build on pushes to `main`, pull requests and manual
  dispatch.
- README, architecture, backup format, security/privacy, release process,
  roadmap and manual testing documents updated for v1.4.

### Release manifest audit

The final unsigned universal release APK was audited with `apkanalyzer`:

- package `dev.paperos.app`, `versionName=1.4.0`, `versionCode=5`;
- no `android.permission.INTERNET`;
- no `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`,
  `MANAGE_EXTERNAL_STORAGE` or `ACCESS_MEDIA_LOCATION`;
- the only permission is the app-defined signature permission
  `dev.paperos.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`;
- `android:allowBackup="false"`, `android:fullBackupContent="false"`;
- `android:enableOnBackInvokedCallback="true"`;
- exactly one exported activity, `dev.paperos.app.MainActivity`, carrying the
  LAUNCHER, HOME and VIEW filters;
- the VIEW filter advertises `application/pdf`, `application/epub+zip` and
  `text/plain` for both `content` and `file` schemes;
- the only exported receiver is AndroidX's `ProfileInstallReceiver`, protected by
  `android.permission.DUMP`.

The AAB's embedded `base/manifest/AndroidManifest.xml` was inspected with
`strings` because `bundletool` is not installed on this machine. It contains the
same package, `1.4.0`, PDF/EPUB/text filters and the single app-defined
permission; no `INTERNET` string is present. A full bundletool manifest decode
was not performed.

The debug APK was also audited: package `dev.paperos.app.debug`, version
`1.4.0-debug` (5), permissions are the app-defined debug permission plus
`android.permission.INTERNET`. That permission exists only for Flutter tooling
and is not release evidence.

## Release readiness

**Automated readiness:** yes. Formatting and analysis are clean, all 247 tests
pass, all four Android artifacts build, and the final release manifest has the
expected package, version, filters and permission set.

**Distribution readiness:** no. Two gates remain:

1. **Device validation.** No v1.4 device run exists. Rows 49–58 and the
   previously unverified v1.3 rows must be exercised on a physical device before
   any public release claim.
2. **Production signing.** No owner keystore or credentials were supplied. The
   default release path remains fail-closed; only unsigned analysis artifacts
   were produced.

No release note should describe the device cases, a signed build or a Play
release as complete until those gates are closed.

## Known limitations and unverified items

- No v1.4 device run; every Android runtime row in this report is unverified.
- Production signing is blocked by missing credentials.
- The release APKs are unsigned analysis artifacts and are not installable.
- GitHub Actions has not executed remotely because the branch was not pushed.
- The AAB manifest was inspected through embedded protobuf strings, not decoded
  with bundletool.
- A `.part` file can remain if the process is killed mid-copy; destination files
  remain intact, and successful imports leave no `.part`.
- EPUB parsing runs off the UI isolate when isolates are available, but the
  serialised queue does not make a very large archive parse instantly.
- The app drawer no longer guesses that a short list is a package-visibility
  restriction. A true restriction needs a stronger platform signal than list
  size.
- Backups remain unencrypted and unsigned.
- The automated suite is not an Android instrumentation harness and cannot prove
  IME, SAF, PDF, E-Ink, HOME-role or OEM task behaviour.
